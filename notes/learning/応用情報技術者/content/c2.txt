## CPUの性能
= #MIPS
= 平均CPI ＝ Σ（命令のクロック数 × 出現率）
= 1命令の時間 ＝ CPI ÷ クロック周波数
= MIPS ＝ 1 ÷ 1命令の時間 ÷ 10⁶
= 例）700MHz、CPI＝4×0.3＋8×0.6＋10×0.1＝7 → 700÷7 ＝ 100MIPS
> 割込みで食われる分は引くだけ（100MIPSで毎秒10⁷命令取られたら残り90MIPS）

## CPUを速くする
= #+ パイプラインの実行時間
= (命令数N ＋ 段数D − 1) × ピッチP      例）N=5, D=4 → 8ピッチ
@fig pipeline | パイプライン（F取出し D解読 R読出し E実行）| 1つずつずらして同時進行。5命令が8ピッチで終わる
(
+* パイプラインハザード — 分岐などで先読みがムダになる
+ 投機実行 — 分岐先を予測して先に実行しておく
+ 遅延分岐 — 分岐に影響しない命令を分岐の後ろに置いて先に実行
+ スーパパイプライン — 段数を増やす
+* スーパスカラ — パイプラインを複数並べる。並べ方は**実行時**にハードが決める
+* VLIW — 同時に動かせる命令を**コンパイル時**に1つの長い命令にまとめる
- SIMD — 1命令で複数データ（GPUはこれ）。MIMD＝複数命令×複数データ
+ GPGPU — GPUを画像以外（ディープラーニングの行列計算など）に使う
- RISC — 単純・固定長命令でパイプライン向き。CISC＝複雑で多機能
)
( マルチプロセッサ
+* 密結合 — 主記憶を共有・OS1つ。メモリの取り合い（排他制御）で台数に比例して速くならない
+ 疎結合 — 主記憶もOSも別々。通信でつなぐ
)

| 用途 | キャッシュ | 主記憶 |

( フラッシュメモリ（不揮発）

## キャッシュ
= #実効アクセス時間
= キャッシュ時間 × ヒット率 ＋ 主記憶時間 × (1 − ヒット率)
= 例）10ns・60ns・ヒット率90% → 10×0.9＋60×0.1 ＝ 15ns
! 容量（Mバイト）は計算に使わない。ひっかけで書いてある
(
+ 局所参照性 — 近いうち・近い場所がまた使われる性質。これがあるからキャッシュが効く
+ ダイレクトマッピング — 置き場所が1か所に決まる（指定席）
+ フルアソシエイティブ — どこでもOK（自由席）
+* セットアソシエイティブ — 決まったセットの中ならどこでも（車両指定の自由席）
-* ライトスルー — キャッシュと主記憶に**同時に**書く。一致してるが遅い
-* ライトバック — キャッシュだけ書いて、**追い出されるとき**に主記憶へ。速い
+ コヒーレンシ — キャッシュと主記憶の内容の一貫性
)

## RAID
@fig raid | RAIDの並べ方
(
+ RAID3 — ビット単位＋パリティ専用ディスク
+ RAID4 — ブロック単位＋パリティ専用ディスク（書込みが集中）

= #+ RAIDの稼働率（1台の稼働率 u）
= RAID0（2台）  ＝ u²                 2台とも動く必要
= RAID1（2台）  ＝ 1 − (1−u)² ＝ 2u − u²
= RAID5（5台）  ＝ u⁵ ＋ ₅C₄u⁴(1−u) ＝ 5u⁴ − 4u⁵   4台以上動けばOK
= 容量400GBをRAID5で（1台100GB）→ 400＋パリティ100 ＝ 5台

## 信頼性と稼働率
( RASIS
- R 信頼性 — 壊れにくい → MTBF
- A 可用性 — 使える → 稼働率
- S 保守性 — すぐ直る → MTTR
- I 保全性 — データが矛盾しない
- S 安全性（機密性） — 漏れない
)
= #稼働率
= 稼働率 ＝ MTBF ÷ (MTBF ＋ MTTR)
= 直列 ＝ A₁ × A₂          並列 ＝ 1 − (1−A₁)(1−A₂)
= 3台中2台以上 ＝ 3A² − 2A³
= 故障率 ＝ 1 ÷ MTBF      直列の故障率 ＝ 各故障率の和
@fig availability | 基本情報まとめの図そのまま
(
+ MTBF＝MTTRのとき — 稼働率0.5
+ MTTRを縮める — エラーログ取得・遠隔保守・保守センタ分散
+ 比べる問題 — 2つの式の**差をとって符号を見る**
)
! 稼働率を上げる対策が **MTBFを延ばす**（予防保守・高信頼部品）か **MTTRを縮める**（遠隔保守・エラーログ）かを区別させる問題が出る

## 性能評価
(
- スループット — 単位時間の処理量
- レスポンスタイム — 入力終わり→**最初の応答が出始める**まで
- ターンアラウンドタイム — 投入→**結果が全部出終わる**まで
+ SPECint／SPECfp — 整数／浮動小数点のベンチマーク

-* スケールアウト — 台数を増やす → 参照中心（Webサーバ）向き
-* スケールアップ — 1台を強くする → 更新が多いDBサーバ向き
)
= #+ アムダールの法則
= 全体の速さ ＝ 1 ÷ { (1 − a) ＋ a ÷ V }     a：速くした部分の割合、V：その倍率
= 例）60%の処理だけ6倍 → 1 ÷ (0.4 ＋ 0.1) ＝ 2倍
= CPU数 ＝ 必要なCPU時間 ÷ 使用率の上限（2.4秒分÷60% → 4個）

## 作り方と電力
(
+* FPGA — 現場で回路を書き換えられるIC。HDLで書く→論理合成→配置配線→書込み
+ SystemC — C++ベースでハードとソフトを一緒に設計（コデザイン）
+ ダイナミック電力 — 動くと食う。電圧²×周波数に比例
+* クロックゲーティング — 使わない回路への**クロック**を止める
+* パワーゲーティング — 使わない回路の**電源**を切る（リーク電流対策）
+ DVFS — 負荷に応じて電圧と周波数を変える
)

## 組込み
@flow センサ::測る >[A/D変換] コンピュータ::判断 >[D/A変換] +アクチュエータ::電気信号→動き
(
+* ジャイロセンサ — **角速度**（回転）
+ ホール素子 — 磁気
+ サーミスタ — 温度
+ ひずみゲージ — 物の変形
+ TOF — 光が往復する時間で距離
+* PWM — ON時間の割合（デューティ比）でモータの速さを制御
+ DSP — 積和演算が得意な信号処理用プロセッサ
+ SoC — システムを1チップに。ASIC＝特定用途向けIC、MEMS＝微細な機械＋電子
+ 逓倍器 — 周波数をN倍（PLL）。分周器＝1/N（T-FF）
)
= #+ A/D・D/A変換
= A/Dの値 ＝ (入力 − 最小値) ÷ (レンジ幅 ÷ 2^ビット数)
= 例）−5〜＋5V・8ビットで＋2.5V → 7.5 ÷ (10/256) ＝ 192 ＝ C0₁₆
= D/Aの出力 ＝ データ値（10進）× 1ビットの重み（82₁₆＝130 → 130×10mV＝1.3V）

## ＋α ヒューマンインタフェース・マルチメディア
(
+ ユーザビリティ — 特定の利用者が、有効さ・効率・満足度をもって目的を達成できる度合い
+ アクセシビリティ — 高齢者・障害者も含めて誰でも使える（JIS X 8341）
+ ユニバーサルデザイン — 最初から誰でも使いやすく設計
+ ペルソナ — 典型的な利用者像を具体的に作った架空の人物
+ ヒューリスティック評価 — 専門家が経験則に照らして問題点を洗い出す
+ 思考発話法 — 考えてることを声に出しながら操作してもらう
+ カードソーティング — カードを分類してもらってサイト構造を決める
)
(
- 可逆圧縮 — 完全に戻せる：PNG・GIF・ZIP
- 非可逆圧縮 — 戻せない代わりに高圧縮：JPEG・MPEG・MP3
+ レンダリング — 3Dデータから2D画像を作る。レイトレーシング＝光線を追う
+ テクスチャマッピング — 表面に模様を貼る。アンチエイリアシング＝ギザギザを消す
+ VR／AR／MR — 仮想に入る／現実に重ねる／現実と仮想が相互に作用
- 光の三原色RGB — 加法混色（重ねると白）。印刷はCMY（K）で減法混色
