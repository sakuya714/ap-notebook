## E-R図とキー
(
-* 1対多 — **多の側**が1の側の主キーを**外部キー**として持つ
+* 多対多 — 間に**連関エンティティ**を入れて1対多×2に。その主キー＝両側の主キーの組
+ E-R図の穴埋め — 主キーを持つ側が「1」、外部キーを持つ側が「多」
+ 「1回の請求を複数回で入金」「複数の請求を1回で入金」 — 両方あれば多対多
)
( キー
- 候補キー — 行を1つに決められる**最小**の列の組
-* 主キー — 候補キーから1つ。**重複不可＋NULL不可**
+ 代替キー — 主キーに選ばれなかった候補キー
- 外部キー — 他の表の主キーを参照
)

## 正規化
@stack 正規化の階段（下に行くほど分ける）
非正規形 :: 1人に資格が何行もぶら下がる（繰返し）
第1正規形 :: 繰返しをなくす（1マス1値）
第2正規形 :: **主キーの一部**だけで決まる列を分ける（部分関数従属）
第3正規形 :: **主キー以外**で決まる列を分ける（推移的関数従属）
+ボイス・コッド正規形 :: 決定する側が必ず候補キー
@end
(
- 関数従属 X→Y — Xが決まるとYが1つに決まる
+* 第2正規化が起きるのは — 主キーが**複数列**の表だけ
+ どこまで正規化されてる？ — 主キー1列なら第2以上確定→キー以外どうしの従属があれば第3じゃない
+ 正規化の目的 — 更新時異状（データ矛盾）を防ぐ。欠点は結合が増えて遅い→あえて崩す＝非正規化
)

## 制約と表定義
| 制約 | 書き方 | 意味 |
| 主キー | PRIMARY KEY | 一意＋NOT NULL |
+| 一意性 | UNIQUE | 重複NG。**NULLはOK** |
| 非ナル | NOT NULL | 空値NG |
| 参照 | REFERENCES / FOREIGN KEY | 外部キー |
+| 検査 | CHECK(単価 > 0) | 条件を満たすか |
( 参照動作（参照されてる行を消す・変えるとき）
+ NO ACTION — 既定。制約違反なら失敗
+ RESTRICT — 参照されてたら拒否

)
! 参照制約で拒否されうるのは「外部キー側への追加」と「参照される側の削除」

## SELECTを読む
@flow FROM::表・直積 > WHERE::行を絞る > GROUP BY::まとめる > HAVING::グループを絞る > SELECT::列を選ぶ > ORDER BY::並べる || この順に仮の表を書いていけば必ず読める
(
-* 選択 — **行**を取り出す＝WHERE
-* 射影 — **列**を取り出す＝SELECT
- 結合 — 共通列で2表をつなぐ＝直積＋選択
- 和・差・積 — UNION／EXCEPT／INTERSECT（同じ列構成どうし）
+* 集合関数はWHEREで使えない — SUM・AVG・COUNTはHAVINGかSELECTで
+ COUNT(*) — NULL行も数える。COUNT(列)＝NULLを除く
+* 同姓同名を探す — GROUP BY 氏名 HAVING COUNT(*) > 1
- LIKE — `%`＝0文字以上、`_`＝1文字
+ NULLの判定 — `IS NULL`（`= NULL`は書けない）
)

## 結合と副問合せ
(
- 内結合 — 両方にある行だけ
+* 左外結合 — 左の表は全部残す。相手がなければNULL→**行数≧左の表の行数**
+ 副問合せ — （SELECT…）の結果を使う。比較演算子と使うなら1行1列が必要
+* 相関副問合せ — 副問合せの中に**外側の表**が出てくる。外側の1行ずつ実行
+* EXISTS — 1行でもあれば真。NOT EXISTS＝1行もなければ真
)
! NOT EXISTSの境界：「在庫数＞30」に30は入らない。外側の表を1行ずつトレースする

## 更新とビュー
(
- UPDATE・DELETE — **WHEREを書き忘れると全行**
+ UNIQUE違反の判定 — NULLを含む組は重複扱いにならない。既にある組を作ったらNG
+* ビュー — 名前を付けた導出表（仮想の表）。実データは持たない
+* 更新できないビュー — 集合関数・DISTINCT・GROUP BY・HAVING・計算式がある（元の行に戻せない）
- GRANT／REVOKE — 権限を与える／取り消す
)

## トランザクション
( ACID
-* A 原子性 — 全部やるか、全くやらないか
- C 一貫性 — 前後で矛盾しない
-* I 隔離性（独立性） — 同時に動かしても順番にやったのと同じ結果（直列可能性）
-* D 耐久性 — コミットしたら障害が起きても消えない
)
( 同時実行の問題
- ロストアップデート — 後の更新で先の更新が消える
+ ダーティリード — **未コミット**のデータを読む
+ ノンリピータブルリード — 2回読んだら間に**更新**されて値が違う
+ ファントムリード — 2回検索したら間に**追加**されて行が増えてる
)
| 相手→ | 共有ロック | 専有ロック |
| 共有ロック中 | ○ | × |
| 専有ロック中 | × | × |
(
+* 2相ロック — 使うものを全部ロック→終わったら全部解除。解除後は再ロックしない→直列可能性を保証
+ ロックの粒度 — 小さい（行）ほど並行性↑・管理の手間↑
+ 分離レベル — READ UNCOMMITTED＜READ COMMITTED＜REPEATABLE READ＜**SERIALIZABLE**（一番厳しい）
+ 楽観的排他制御 — ロックせずに処理し、更新時に**変更されていないか確認**（版番号）
+ WAL（ログ先行書込み） — DBを更新する**前に必ずログ**を書く
)

(
-* 更新前ログ — 取り消す＝**ロールバック**（後退復帰）
-* 更新後ログ — やり直す＝**ロールフォワード**（前進復帰）
+* 媒体障害 — バックアップをリストア→その後の更新後ログでロールフォワード

@fig recovery | システム障害からの回復 | チェックポイント前に終わってたら何もしない／コミット済みはやり直す／未コミットは取り消す

+ 差分バックアップ — フル以降の変更。復元は「フル＋最新の差分」
+ 増分バックアップ — 前回以降の変更。復元は「フル＋全部の増分」
)

## LANの送り方
(
-* CSMA/CD — 有線。空いてたら送る→**衝突を検出**したら待って再送。使用率30%くらいから遅延が急増
+* CSMA/CA — 無線。衝突は検出できないので**避ける**：空いてても少し待つ＋ACKで確認
+ 隠れ端末問題 — 端末同士が見えずにAPで衝突 → RTS/CTSで予約
- トークンパッシング — 送信権の札を持ってる人だけ送る。衝突なし
)
| 802.11 | 周波数 | 最大速度 |
| a | 5GHz | 54Mbps |
| b | 2.4GHz | 11Mbps |
| g | 2.4GHz | 54Mbps |
+| n | 2.4/5GHz | 600Mbps（MIMO） |
+| ac | 5GHz | 約7Gbps |
+| ax（Wi-Fi 6） | 2.4/5GHz | 9.6Gbps |
(
- インフラストラクチャモード — アクセスポイント経由。アドホック＝端末同士で直接
+* リンクアグリゲーション（802.3ad） — 複数の回線を**束ねて1本に**。速い＋1本切れても大丈夫
+* PoE（802.3af） — **LANケーブルで給電**。APやカメラの電源工事がいらない
+* スパニングツリー（802.1D） — ループ状の配線で一部ポートを止めて**ブロードキャストストーム**を防ぐ
+ VLAN（802.1Q） — スイッチの設定で論理的にLANを分ける。VLAN間はルータが必要
+ LPWA — 省電力で数km〜届く。IoTセンサ向き
+ MQTT — IoT向け軽量プロトコル。ブローカを介してpub/sub
)

## IPv4
(
-* プライベートIP — 10.0.0.0/8、172.16〜172.31、**192.168.0.0〜192.168.255.255**

## ルーティング・NAT
(
- ルーティングテーブル — 宛先ネットワークとネクストホップ。どれにも当てはまらない時はデフォルトルート 0.0.0.0/0
+* RIP — ディスタンスベクタ型。**ホップ数**が最小。30秒ごと交換。最大15
+* OSPF — リンクステート型。**コスト**が最小。リンクステートデータベースで全体の地図を持つ
+ IGP／EGP — AS（組織）の中／AS同士（BGP）
-* NAT — IPアドレスだけ1対1で変換
-* NAPT（IPマスカレード） — **IP＋ポート番号**を変換→1つのグローバルIPを複数台で共有
+ NAPTの穴埋め — 応答は「要求の送信元と宛先を入れ替えたもの」。ルータは覚えた変換を元に戻す
)
( ネットワークの仮想化
+* SDN — 「どこへ送るか決める（制御）」と「送る（転送）」を**分けて**、コントローラで集中制御。OpenFlow
+* NFV — FW・ルータなど専用機器の機能を**汎用サーバの仮想マシン**で動かす
)

(
+ ブロック暗号／ストリーム暗号 — ブロックごと（AES）／1ビットずつ（RC4・KCipher-2）
+ 危殆化 — 計算機の進歩などで暗号の**安全性が下がる**こと。耐量子計算機暗号＝量子コンピュータでも解けない暗号
+* ハッシュ関数 — 長さ関係なく**固定長**。少し違うと全然違う値。戻せない（一方向性）・同じ値を作れない（衝突発見困難性）。SHA-256＝256ビット
)

## 鍵の使い分け（最重要）
@fig keys | 誰の・どっちの鍵？
> 暗号化は「受信者の」、署名は「送信者の」。ここを入れ替えた選択肢が毎回出る
(
+* 認証局（CA） — デジタル証明書（X.509）を**作って発行**する第三者機関
+ 証明書の中身 — 持ち主の名前（FQDN）・持ち主の公開鍵・有効期間・CAのデジタル署名
+* CRL — **有効期限内に**失効させた証明書の**シリアル番号**の一覧
+ OCSP — 証明書が有効かをオンラインでリアルタイム確認
+ PKI — 公開鍵を使って身元を保証する仕組み全体
+ MAC／HMAC — 共通鍵＋ハッシュで改ざん検知。共通鍵なので**否認防止はできない**（署名との違い）
+ タイムスタンプ（時刻認証） — その時刻に存在し、以降**改ざんされていない**ことの証明
)
